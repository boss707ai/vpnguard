# Инструкция для кодинг-агента: адаптировать VPN Guard под VPN пользователя

Ты — кодинг-агент (Claude Code, Codex, Cursor и т. п.) в этом репозитории. Задача — чтобы VPN Guard работал с VPN-клиентом пользователя. Обычно для этого нужен **один новый файл**: адаптер `providers/ИМЯ/provider.sh`. Ядро трогать не нужно.

Прочитай: [README.md](README.md) (что делает защита), [docs/ADAPTERS.md](docs/ADAPTERS.md) (интерфейс и шаблон адаптера), [providers/karing/provider.sh](providers/karing/provider.sh) (рабочий образец).

## Правила безопасности

1. **В pf — только решения по интерфейсу и адресу назначения.** Никаких `user`, `group`, `route-to`, `rdr` и прочего, что уводит pf в другие части ядра. Проверки владельца пакета в pf могут повесить ядро macOS. Установщик такие правила и так не пропустит.
2. **Не снимай работающую защиту пользователя.** Не трогай pf, launchd и `/Library/Application Support/VPNGuard`. Не проси у пользователя пароль, чтобы что-то обойти. Всё попадает в систему только через `sudo ./install.sh`: пользователь запускает его сам, видит diff и отвечает `y`. Перед этим объясни ему, что именно меняется.
3. **Без секретов.** Не выводи и не коммить UUID, ключи, пароли и ссылки подписок из конфигов клиента. В тестах — только учебные адреса: `192.0.2.x`, `198.51.100.x`, `203.0.113.x`, `*.example.net`.
4. **Ничего не зашивай руками:** ни IP серверов, ни имена интерфейсов. Адреса — только из настоящих настроек клиента.
5. **Сначала разведка, потом код.** Если что-то не выходит, не обходи защиту ядра, а спроси пользователя.

## Порядок работы

1. **Разведка.** Дай пользователю команды без sudo. Он их выполнит и пришлёт вывод. Выясни:
   - как клиент называется, где на диске его настройки и в каком формате (`ls ~/Library/Group\ Containers`, `ls ~/Library/Application\ Support`, `scutil --nc list`);
   - где в настройках адреса VPN-серверов и к каким DNS клиент ходит напрямую, до подъёма туннеля;
   - поднимает ли клиент туннель: при подключении маршрут по умолчанию идёт через `utunN` (`route -n get default`). Если клиент работает только как системный прокси, без туннеля, VPN Guard ему не подходит — скажи об этом прямо;
   - есть ли у клиента раздельная маршрутизация («российские сайты напрямую») и по какому списку. Защита пускает напрямую только сети из `pf/ru.cidr`;
   - есть ли у клиента локальный прокси «всё напрямую» (адрес и порт).
2. **Адаптер.** Создай `providers/ИМЯ/provider.sh` по шаблону из `docs/ADAPTERS.md`. Разбор настроек должен быть строгим: всё непонятное — в `bad`, а не в догадку.
3. **Тесты.** В `tests/test_state.sh` добавь разбор образца настроек клиента: учебные адреса, мусор, пустой файл, не тот формат. Прогони:
   ```bash
   bash tests/test_state.sh && bash tests/test_textcheck.sh && bash tests/test_daemon_sim.sh
   ```
   Все три без `FAIL`. Симуляция идёт около минуты и грузит процессор — предупреди пользователя.
4. **Проверка на машине** (без sudo, ничего не меняет): `./precheck.sh --provider ИМЯ`. Нужен `ВЫВОД: совместимо`.
5. **Установка — делает пользователь:** `sudo ./install.sh --provider ИМЯ`, потом приёмка `sudo "/Library/Application Support/VPNGuard/tests/acceptance.sh" --vpn-off`. Нужен `FAIL=0`. Если что-то упало, разберись по `acceptance.log` и `vpnguard log`, не ослабляя правила.
6. **Оформи:** добавь строку в таблицу клиентов в README и закоммить. Если пользователь хочет поделиться адаптером — помоги открыть pull request.

## Промт для пользователя

Скопируй в своего кодинг-агента, открытого в папке репозитория:

```
Прочитай AGENTS.md и сделай адаптер VPN Guard под мой VPN-клиент: [НАЗВАНИЕ].
Начни с разведки: дай мне команды без sudo, я пришлю вывод.
```
