# Адаптеры VPN-клиентов

Ядро VPN Guard от клиента не зависит. Правила pf, сторож, иконка, пауза с паролем, установщик и тесты одинаковы для любого VPN, который на macOS поднимает туннель `utun`, `ipsec` или `ppp`.

Адаптер отвечает на один вопрос: **куда этому клиенту нужно ходить напрямую, мимо туннеля**. Ответ — это адреса его VPN-серверов и DNS-серверов, к которым клиент ходит до подъёма туннеля. Всё остальное ядро делает само: проверяет каждый адрес, разрешает имена через публичный DNS по HTTPS, собирает таблицы pf, шлёт уведомления о новых серверах.

## Где лежит и как ставится

```
providers/
└── ИМЯ/
    ├── provider.sh   ← адаптер (обязателен)
    └── …             ← утилиты клиента по желанию (например, karing/geosite-off.sh)
```

- `ИМЯ` — строчная латиница, цифры и дефис, до 32 символов: `karing`, `wireguard`, `openvpn`.
- Установка с адаптером: `sudo ./install.sh --provider ИМЯ`. Установщик кладёт его в `/Library/Application Support/VPNGuard/provider.sh` (root, 644). Обновление (`vpnguard update`) оставляет прежний адаптер.
- Адаптер — код, который исполняется в том числе от root. Поэтому он проходит те же проверки, что и остальной код: белый список символов, `bash -n`, полный diff перед `y`.

## Что адаптер определяет

`provider.sh` подключается через `.` из CLI, сторожа, precheck, приёмки и тестов. **На верхнем уровне — только присваивания и функции**, никаких команд и вывода: это проверяет `tests/test_state.sh`.

| Имя | Обязательно | Что это |
|---|---|---|
| `VG_PROVIDER` | да | имя, совпадает с папкой |
| `VG_PROVIDER_TITLE` | да | название для людей: «Karing», «WireGuard» — подставляется в сообщения, уведомления и меню |
| `vg_provider_extract` | да | функция: печатает выжимку (формат ниже) |
| `vg_provider_precheck` | да | функция: проверки клиента для `precheck.sh` |
| `VG_PROVIDER_RU_SRC` | нет | файл, из которого клиент берёт свой список российских IP; по его sha256 ядро замечает, что клиент обновил список. Пусто — сверки нет |
| `VG_PROVIDER_PROXY_DIRECT` | нет | `адрес:порт` локального прокси клиента «всё напрямую», если он есть. Самотест и приёмка проверяют, что через него за рубеж не уйти |

Установщик до подтверждения адаптер **не исполняет**. `VG_PROVIDER`, `VG_PROVIDER_TITLE` и `VG_PROVIDER_RU_SRC` он читает из текста, поэтому пишите их одной строкой в двойных кавычках, без подстановок: `VG_PROVIDER_TITLE="WireGuard"`.

### `vg_provider_extract` — выжимка

Запускается **от пользователя, не от root**. Иконка вызывает её раз в 10 секунд через `vpnguard sync -q`, вручную — `vpnguard sync`. Данные других приложений macOS отдаёт только процессам пользователя с разрешением, поэтому сторож сам их не читает.

Успех — `rc=0` и строки:

```
server АДРЕС        # VPN-сервер: IPv4, IPv6 или имя хоста
dns ТИП АДРЕС       # DNS, к которому клиент ходит напрямую: ТИП — udp, tcp, tls, https, quic или h3
bad ЧТО-УГОДНО      # непонятная запись: ядро запишет её в журнал и пропустит
```

Ошибка — `rc=1` и одна строка `error КОД текст для человека`. `КОД`:
- `denied` — macOS не пускает к данным клиента;
- `missing` — нет файла настроек;
- `unreadable` — всё остальное.

Выжимке ядро **не доверяет**. `vg_parse_extract` пропускает только адреса и имена хостов. DNS по имени не берётся: имя разрешилось бы во что угодно и открыло бы туда порты DNS. Больше 64 записей не берётся. Каждый новый сервер — уведомление пользователю. Но защита от подлога начинается с адаптера: берите адреса **только из настоящих настроек клиента**, не из файлов, которые может подложить кто угодно.

### `vg_provider_precheck` — проверка до установки

Печатает результаты через функции `ok`, `warn` и `stop` из `precheck.sh`. Ничего не меняет. Обычно проверяет:
- клиент установлен;
- он подключён и интернет идёт через туннель;
- его настройки читаются.

Выжимку кладёт в переменную `VG_PRECHECK_EXTRACT`. По ней precheck сам проверит серверы через публичный DNS.

## Шаблон

```bash
# Адаптер VPN Guard для ИМЯ_КЛИЕНТА. Только определения, без команд на верхнем уровне. docs/ADAPTERS.md.

VG_PROVIDER=имя
VG_PROVIDER_TITLE="Название"
VG_PROVIDER_RU_SRC=""
VG_PROVIDER_PROXY_DIRECT=""

# vg_provider_extract → выжимка: «server АДРЕС», «dns ТИП АДРЕС», «bad …»; ошибка — «error КОД текст», rc=1
vg_provider_extract() {
  local conf="$HOME/путь/к/настройкам"
  [ -e "$conf" ] || { echo "error missing нет настроек Название: $conf"; return 1; }
  [ -r "$conf" ] || { echo "error denied macOS не пускает к настройкам Название — разреши доступ"; return 1; }
  # разбор настроек → строки выжимки (пример для строк вида «Endpoint = host:port»)
  sed -n 's/^[[:space:]]*Endpoint[[:space:]]*=[[:space:]]*\(.*\):[0-9]*[[:space:]]*$/server \1/p' "$conf"
}

# vg_provider_precheck → проверки клиента через ok/warn/stop; выжимка → VG_PRECHECK_EXTRACT
vg_provider_precheck() {
  local out
  VG_PRECHECK_EXTRACT=""
  if out=$(vg_provider_extract); then ok "настройки Название читаются"; VG_PRECHECK_EXTRACT=$out
  else stop "${out#error * }"; fi
}
```

## Готово, когда

1. `bash tests/test_state.sh` — контракт адаптера проходит. Добавлены тесты на разбор настроек клиента: образец настроек с **учебными** адресами (`192.0.2.x`, `198.51.100.x`, `203.0.113.x`, `*.example.net`) и мусором.
2. `bash tests/test_daemon_sim.sh` и `bash tests/test_textcheck.sh` проходят.
3. `./precheck.sh --provider ИМЯ` на живой машине, с подключённым клиентом: `ВЫВОД: совместимо`.
4. После `sudo ./install.sh --provider ИМЯ` приёмка проходит: `sudo "/Library/Application Support/VPNGuard/tests/acceptance.sh" --vpn-off` даёт `FAIL=0`. Особенно важен пункт 3.9: клиент подключается при включённой защите.
5. В README в таблицу клиентов добавлена строка.
